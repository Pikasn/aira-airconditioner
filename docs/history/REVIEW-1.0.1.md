# 1.0.1 设备控制审查记录

日期：2026-10-15。范围：前端联动、设备适配、状态管理、接口、凭据存储与 Windows 启动器。

## 已修复

| 问题 | 修复结果 |
| --- | --- |
| 驱动的 `retry_count=1` 表示额外重试，回执丢失时可能重发控制 | 改为零次重试；异常后只握手和读取状态，不重发控制。用真实 SDK 配合模拟 UDP 丢包复现并验证发送次数。 |
| 多个页面同时操作时，后端会排队执行过时的指令 | 设备忙时立即拒绝新的写入；前端仍合并连续调温并串行提交。 |
| 从已保存配置启动后，首次控制可能跳过型号验证 | 在读取和控制前完成型号验证；型号不匹配时不发送控制。 |
| 缺失或异常的功率读数导致正常空调状态读取失败 | 独立解析可选功率，异常值记为未知，保留有效的控制状态。 |
| 接口只检查声明的请求长度 | 增加实际长度与一致性检查，拒绝不支持的传输方式。 |
| 新解压副本可能复用另一目录或旧版本的服务 | 启动器核对目录指纹与版本；停止操作也核对服务归属。 |
| 依赖清单更新后，已有环境可能跳过安装 | 根据依赖清单指纹同步环境，安装成功后才保存指纹。 |

配置切换同时提交设备信息与状态，避免请求读到混合的新旧连接信息。

## 验证结果

- 56 项自动化测试通过，包括协议映射、异常状态、丢包后的单次发送、并发写入拒绝、型号校验、凭据保护、接口限制与启动器行为。
- 7 组浏览器联动场景通过：连接与能力限制、连续调温合并、慢响应处理、失败恢复、关机丢弃未发送设置、断线重连、不同屏宽布局。未发现浏览器脚本错误。
- 浏览器控制场景使用隔离的模拟设备，不向真实伴侣发送红外控制。
- 在原项目目录实际验证了启动、复用、停止与重启，服务版本为 1.0.1。实际连接页和主界面检查通过，真实米家空调伴侣 2 的状态查询成功。
